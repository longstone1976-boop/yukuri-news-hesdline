# ゆっくりNEWS（収集と要約）

登録したRSSから記事を集め、Gemini で見出しと概要を要約して PostgreSQL に保存し、一覧と詳細の画面で見られるようにするプログラムです。仕様書（2026/10/17版）のうち、次の部分を実装しています。

| 仕様書 | 実装内容 |
|---|---|
| 2.2・2.3 要約AI連携 | 25文字を超える見出しと、250文字を超える本文を Gemini で要約。失敗の判定、代わりの説明文、再要約（最大2回） |
| 3章 記事収集 | 毎日 6:00／11:55／16:00（日本時間）、直近24時間・サイトごと最新20件、同じURLは1件、収集済みは取り直さない、200件を超えたらサイトごとに均等に選ぶ、一覧から外れて24時間で削除 |
| 4章 ニュースフィールド | 1ページ21件（3列×7行）、「現在／総ページ数」、左下「戻る」・右下「進む」 |
| 5章 記事詳細 | 見出し・サムネイル・概要・投稿日時、記事参照（新しいタブ） |
| 5.2 サムネイル | RSSの画像 → og:image → twitter:image → No Image |
| 8.4 収集元URL | 追加（フィードを読めるか確認・サイト名を自動取得・重複不可・上限20件）、複数選んで削除 |

**会員まわり（8章・9章）**：新規登録（仮登録→確認用URLで本登録、ユーザーID発行）、ログイン（5回失敗で15分停止、30日保持）、パスワードリセット、MYページ（メールアドレス変更・パスワード変更・収集元URLの追加/削除・退会）。ニュース一覧はユーザーごとに、その人が登録したサイトの記事だけで作ります。

**メールはモック**：実際には送らず、DBの `mock_mails` に保存します。本人が操作した画面にはその場でメールの中身を表示し、ログインしていない人のパスワードリセットなど他人に見られると困るメールは、管理者画面の「モック受信箱」（/admin/mails）でだけ見られます。本番化するときはメール配信サービスにつなぎ替えます。

**管理者画面（/admin）**：環境変数 `APP_USER`（ログインID）・`APP_PASSWORD` でログイン。今すぐ収集・収集結果・会員数・登録されている収集元・モック受信箱を見られます。

**今回の範囲外**：閲覧履歴・clip。

## 構成

- Node.js 22 ＋ Express（画面）
- PostgreSQL（記事・収集元・収集の記録）
- Gemini API（`generateContent`、APIキーはサーバーの環境変数だけに置く）
- 自動収集：サーバーの中のスケジューラー（または Cron Job）

## Render へのデプロイ手順

1. このフォルダを GitHub の**非公開**リポジトリに入れる（`.env` は入れない）。
2. Render にログインし、**New ＞ Blueprint** でそのリポジトリを選ぶ。`render.yaml` を読み込んで、Webサービスと PostgreSQL が作られます。
3. 途中で聞かれる環境変数を入力する。
   - `GEMINI_API_KEY`：Google AI Studio で発行したキー
   - `APP_PASSWORD`：画面を開くためのパスワード（12文字以上）
4. プラン（料金）を選んでデプロイする。
5. 表示されたURLを開き、ログイン画面の「新規登録」から会員登録する（確認用メールは画面にモックで表示されます）。
6. MYページで収集元のRSSのURLを追加し、`/admin` に管理者でログインして「今すぐ収集」を押す。数分後に「ニュース」画面に記事が出れば完了です。

### 自動収集についての注意（無料プランの場合）

Render の無料プランはアクセスがないとサーバーが止まり、サーバーの中の自動収集も動きません。そのため、GitHub Actions（`.github/workflows/collect.yml`）から毎日 6:00／11:55／16:00（日本時間）にアプリを呼び出し、サーバーを起こしてから収集させています。最初に一度だけ、次の設定が必要です。

1. 20文字以上のランダムな文字列（合言葉）を1つ決める。
2. Render の Webサービス「yukkuri-news」の **Environment** で `CRON_TOKEN` にその文字列を入れて保存する。
3. GitHub のリポジトリの **Settings ＞ Secrets and variables ＞ Actions ＞ New repository secret** で、名前 `CRON_TOKEN`、値に同じ文字列を登録する。
4. GitHub の **Actions ＞ 定期収集 ＞ Run workflow** で手動実行し、緑のチェックになれば設定完了。

注意：GitHub の定期実行は混雑時に数分〜十数分遅れることがあります。また、リポジトリに60日間更新がないと定期実行が自動で止まるため、そのときは Actions の画面で有効にし直してください。有料プランにした場合は、この仕組みがなくてもサーバーの中の自動収集が動きます。

## Gemini APIキーについて

- キーは Render の環境変数にだけ入力し、コードやファイル、仕様書には書かないでください。
- 2026年5月以降、Google AI Studio で新しく作るキーは「認証キー」（`AQ.` で始まる形式）が標準になっています。このプログラムは公式の方法どおり、ヘッダー `x-goog-api-key` でキーを送ります。もし収集画面のメモや Render のログに `401` や `ACCESS_TOKEN_TYPE_UNSUPPORTED` が出る場合は、キーの種類や制限の設定が原因です。AI Studio でキーの設定を確認するか、キーを作り直してください。
- Google Cloud の画面で、利用額のアラートと上限を設定しておくことをおすすめします。登録するサイトが増えるほど、要約の回数（料金）が増えます。
- 無料枠は1日の呼び出し回数が少ない（例：1日20回）ため、記事10件ずつまとめて1回で要約しています（`GEMINI_BATCH_SIZE` で変更可）。1日20回なら約200件まで要約できます。
- モデル名は `GEMINI_MODEL` で変えられます（初期値 `gemini-3.5-flash`）。Google がモデルを終了した場合は、ここだけ新しい名前に変えてください。

## 動作の確認方法

- 「収集元URL・収集」画面に、記事数（Gemini で要約した数／要約未完了／代わりの説明文で確定）と、直近10回の収集結果が出ます。フィードを読めなかったサイトは「メモ」欄に出ます。
- 記事詳細画面の下にある「データの確認用」を開くと、元のタイトルと、概要がどこから来たか（Gemini の要約／本文そのまま／RSSの説明文など）を確認できます。

## ローカルで動かす場合

```bash
npm install
# PostgreSQL を用意して接続文字列を設定
export DATABASE_URL=postgres://user:pass@localhost:5432/yukkuri_news
export DATABASE_SSL=false
export GEMINI_API_KEY=（あなたのキー）
export APP_PASSWORD=（12文字以上）
npm start            # http://localhost:3000
npm run collect      # 1回だけ収集して終了
```

## 公開前に確認してほしいこと

- **収集先サイトの利用規約**：記事ページを読み込んで本文を要約します。登録するサイトの利用規約やrobots.txtで、自動での取得や要約が認められているかを確認してください。本文はDBに長く残さず、要約が終わると消します（要約に失敗した記事だけ、再要約が終わるまで残ります）。
- **サムネイル画像**：画像は記事元サイトのものを直接表示しています（DBにはURLだけ保存）。
